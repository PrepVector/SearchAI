================================================================
SEARCH AI -- Claude Code Edition
How to Run the Model
================================================================
(Filename note: "?" is left out on purpose -- it isn't allowed in
Windows filenames.)

There are two ways to run SEARCH AI. Both do exactly the same
research -> outline -> your approval -> full report pipeline. Pick
whichever you're more comfortable with; you can switch between them
any time.

------------------------------------------------------------------
BEFORE EITHER WAY: one-time setup (only needed once per project folder)
------------------------------------------------------------------
1. Make sure python3 is installed and on your PATH.
     python3 --version        (should print 3.9 or higher)

2. Open a terminal in this folder (the one this txt file is in) and
   start Claude Code:
     claude

3. The very first time, accept Claude Code's "trust this folder"
   prompt if one appears. This step matters even if you plan to use
   the dashboard below -- see REQUIRED.txt, item 5, for why.

4. Still inside that Claude Code session, run the setup interview
   once:
     /setup
   Answer its questions (or skip any you don't have an opinion on
   yet -- it ships with sensible defaults).

You only need to do the four steps above once per project folder.

------------------------------------------------------------------
WAY 1 -- Typing the command directly into Claude Code
------------------------------------------------------------------
Inside a Claude Code session in this folder:

     /run-research <a topic you want researched>

     e.g.  /run-research North Star Metric frameworks for B2B SaaS

For a curated-links digest instead of a single deep-dive report:

     /run-research --newsletter <this week's topic/theme>

What happens next:
  - SEARCH AI plans the question, gathers real web evidence if
    needed, and proposes an outline.
  - It STOPS and shows you that outline. Nothing is written in full
    until you approve it, edit it, or ask for changes.
  - Once you approve, it writes the full report, audits it, repairs
    anything that doesn't pass, adds real data-grounded figures if
    they help, and publishes.

The finished report lands at:
     research_runs/<timestamp>_<slug>/output/article.md

------------------------------------------------------------------
WAY 2 -- The browser dashboard (a START button instead of typing)
------------------------------------------------------------------
From a terminal in this folder (does NOT need to be inside an
already-running Claude Code session):

     python3 ui/server.py

or, if you're already inside a Claude Code session in this folder:

     /start-ui

Either way, it opens a browser tab automatically. See "How to
Navigate the Interface.txt" for what to do once it's open.

------------------------------------------------------------------
WHICH WAY SHOULD YOU USE?
------------------------------------------------------------------
- Typing /run-research directly is the more road-tested path -- it's
  exactly what SEARCH AI's own instructions expect, with no layer in
  between.
- The dashboard is newer and a convenience layer on top of the exact
  same pipeline (it runs Claude Code's own headless mode behind the
  scenes). If the dashboard ever seems stuck, every run's Debug info
  panel shows the exact `claude --resume <session_id>` command to
  pick that same conversation up by hand in a terminal -- the
  terminal is always the fallback.

------------------------------------------------------------------
TROUBLESHOOTING
------------------------------------------------------------------
"claude: command not found"
  Claude Code itself isn't installed yet. Run (PowerShell on
  Windows, or your shell on Mac/Linux):
     irm https://claude.ai/install.ps1 | iex        (Windows)
  or see code.claude.com/docs/en/setup for other platforms. If the
  installer says it added a folder to PATH, close and reopen your
  terminal window before trying `claude` again.

"python3: command not found" (Windows specifically)
  Windows sometimes routes `python3` to a broken Microsoft Store
  stub instead of your real install. Fix: Settings -> Apps ->
  Advanced app settings -> App execution aliases -> turn OFF the
  toggles for python.exe and python3.exe, then close and reopen your
  terminal.

A run stops asking permission for something routine
  (running a python3 script, editing a file in this folder, web
  search/fetch). This package ships .claude/settings.json which
  pre-approves those routine calls, but it only takes effect after
  you've accepted the one-time "trust this folder" prompt
  interactively (step 3 above). See REQUIRED.txt for detail.
