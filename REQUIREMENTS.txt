1. WHAT WE ARE BUILDING
--------------------------------------------------------------------------------
SEARCH AI — Claude Code Edition is a research and professional long-form
content-generation agent that runs entirely inside a Claude Code session —
no server, no API key, no separate billing, no pip install. It turns one
typed topic into a premium, outline-bound research article or a curated-
links newsletter edition — grounded in evidence gathered through Claude
Code's own web search, checked against a numbered evidence map, illustrated
only with real data-backed figures (never a stock photo, never an invented
number), validated against the user's exact question, and published as a
clean, properly-cited markdown report.

It is a faithful architectural port of SEARCH AI's API Edition: same
plan -> research -> outline -> write -> audit -> repair -> visualize ->
publish flow, same deterministic guardrails, same delimited-markdown
article format. What differs is the execution shell — every reasoning step
is a Claude Code subagent instead of a direct LLM API call, and every
deterministic step is a stdlib-only CLI script instead of an in-process
function behind a FastAPI route.

Core promise: the approved outline is a contract, the human checkpoint is a
hard stop, evidence is never invented, quality is judged by fixed code
thresholds (not by the model grading its own work), and every run reports
its true final status honestly — a capped repair loop never silently
becomes "PASS."

Explicitly NOT a LinkedIn/social-media tool: no hooks, no scheduling, no
posting to any platform, no engagement analytics, no content-pillar
planning. The output is a markdown file (and, optionally, a PDF) the user
reviews and shares themselves.

2. SYSTEM OUTLINE (THE MODEL'S STRUCTURE)
--------------------------------------------------------------------------------
2.1 Layers
    Claude Code session  ->  /run-research (orchestrating command)
                              -> Subagent layer (LLM reasoning, via Task tool)
                              -> Deterministic layer (stdlib Python scripts)
                              -> Claude Code's own web-search tool
    Optional: Browser dashboard (ui/server.py, local-only) -> same
              /run-research command via `claude -p` headless mode +
              --resume session continuation. No parallel pipeline.

2.2 Pipeline phases
    Phase 1 — Plan + Outline:
        research-planner -> (query-builder -> evidence-scout ->
        source-auditor -> evidence-mapper, only if web search is
        warranted) -> outline-architect -> structural_audit
        (deterministic) -> HUMAN OUTLINE CHECKPOINT (mandatory)
    Phase 2 — Write + Audit + Publish (only after explicit approval):
        research-writer -> outline_contract.py enforce (deterministic)
        -> quality-auditor <-> quality_gate.py (deterministic) <->
        repair-editor, capped at MAX_ITERS (default 4) -> visual-curator
        -> visual_contract.py audit (deterministic) -> final-publisher
        -> render_markdown.py -> research_runs/<run>/output/article.md

2.3 Subagent modules (.claude/agents/, 11 total, all model: inherit)
    research-planner      analysis + Answer Contract + retrieval plan;
                          reads topic, knowledge_base/*.md, and any
                          attached files natively (no separate parser).
    query-builder          turns the plan into 3-6 focused search queries.
    evidence-scout          gathers findings via Claude Code's own web
                          search (never a paid external search API);
                          instructed to never invent a source, product,
                          statistic, or URL.
    source-auditor          mechanical wrapper: runs source_auditor.py
                          (dedupe by domain, flag single-source claims).
    evidence-mapper          mechanical wrapper: runs evidence_mapper.py
                          (numbers findings into [E#] evidence claims).
    outline-architect       proposes layout, 3-12 sections (or, in
                          newsletter mode, an intro + one section per
                          evidence item), each with goal/subpoints/key
                          questions/bridge, plus a narrative thread.
    research-writer         writes the full report in delimited-markdown
                          format from the approved outline + evidence map;
                          register-aware (builder's guide vs. scholarly
                          analyst); newsletter-mode rules built in.
    quality-auditor          nine-category structured audit (see FR-4)
                          plus unsupported-claims/invented-entities/drift
                          lists.
    repair-editor            one targeted correction pass per iteration —
                          "rewrite" (flagged sections) or "polish"
                          (cohesion/clarity only, structure untouched).
    visual-curator           decides per section whether a visual
                          genuinely helps and which archetype; never a
                          forced figure, never a downloaded photo.
    final-publisher          mechanical wrapper: runs final_publisher.py
                          (assembles the References list, strips stray
                          [E#] markers and any model-written ref list).

2.4 Deterministic script modules (scripts/, stdlib-only Python 3.9+)
    new_run.py               scaffolds a run folder + options.json.
    answer_contract.py        Answer Contract shape helpers.
    source_auditor.py          domain-level dedupe, single-source flagging.
    evidence_mapper.py          numbered [E#] evidence claim mapping.
    outline_contract.py         structural_audit (pre-write) + enforce
                              (post-write) — the outline-is-a-contract
                              logic; newsletter-layout-aware.
    article_format.py           parses delimited-markdown into structured
                              article JSON.
    quality_gate.py              fixed-threshold accept/rewrite/polish/
                              fail decision layer — no model call.
    visual_contract.py           post-visual-curator structural check
                              (captions, valid section ids, no duplicate
                              archetypes per section, under image cap).
    visual_engine.py              deterministic SVG figure generation from
                              real labels/data only — no photo search.
    final_publisher.py            References list assembly + marker/
                              reference-list scrubbing.
    render_markdown.py            final article JSON -> output/article.md.
    _jsonio.py                    shared read_json/write_json/die/usage
                              helper so every script shares one CLI shape.

2.5 Slash commands (.claude/commands/)
    /setup                  one-time conversational interview that fills
                          in knowledge_base/research_profile.md,
                          source_rules.md, content_rules.md (and
                          writing_samples.md if a sample is given).
    /run-research <topic> [--newsletter]   the orchestrator (2.2 above).
    /start-ui                launches ui/server.py and opens the browser
                          dashboard.
    /review-memory            view/edit knowledge_base/research_memory.md.
    /add-writing-sample         add a voice sample outside /setup.
    /add-research-rule           add a standing source/content rule
                          outside the periodic feedback prompt.

2.6 Browser dashboard (ui/server.py, optional)
    Stdlib-only local HTTP server (http.server.ThreadingHTTPServer,
    no third-party dependencies) at http://127.0.0.1:8787 — topic box,
    START button, live progress, outline approve/regenerate/discard,
    on-screen report rendering, and one-click PDF download via a small
    hand-written dependency-free PDF writer bundled in ui/server.py. A
    thin control layer that shells out to `claude -p` (headless mode)
    and `--resume` (session continuation) — it does not reimplement or
    bypass any step of the pipeline above. Every run's debug panel shows
    the exact `claude --resume <session_id>` command to continue by hand
    in a terminal if the dashboard ever seems stuck.

3. INPUTS
--------------------------------------------------------------------------------
3.1 User inputs (slash commands or dashboard)
    - topic: free text passed to /run-research or the dashboard's topic box.
    - --newsletter flag (or an unambiguous "this week's newsletter/digest/
      roundup on X" request) selects the Newsletter content type instead
      of the default Article type.
    - outline decision at the mandatory checkpoint: approve as-is / edit
      directly / regenerate with feedback text / discard the run.
    - optional: a different repair-loop cap mentioned in the request
      (default MAX_ITERS = 4; no global setting file, each run is
      independent).
    - optional: attached files (images, PDFs, text, code) — read natively
      by research-planner, no separate upload/parsing step.

3.2 Configuration inputs
    - .claude/settings.json — narrowly-scoped pre-approved permissions
      (see FR-10); takes effect only after Claude Code's one-time
      folder-trust prompt is accepted in an interactive session.
    - knowledge_base/research_profile.md — depth/audience/format defaults,
      seeded via /setup, hand-editable at any time.
    - knowledge_base/source_rules.md — preferred/avoided sources.
    - knowledge_base/content_rules.md — formatting/banned-pattern/
      structural rules.
    - knowledge_base/writing_samples.md — voice references (optional).
    - knowledge_base/research_memory.md — distilled style/preference
      directives + feedback-cadence frontmatter (feedback_every_n).
    - knowledge_base/feedback_log.md — raw feedback history.
    - No .env file, no config.py, no API keys — every subagent runs on
      whatever model the invoking Claude Code session itself is on
      (model: inherit in all 11 agent frontmatters; editable per-agent).

3.3 External data inputs (runtime)
    - Web pages/snippets retrieved through Claude Code's own built-in
      web-search tool only — no paid third-party search API, no direct
      HTTP fetching outside that tool.
    - LLM completions from whatever model the host Claude Code session
      is running.

4. OUTPUTS
--------------------------------------------------------------------------------
4.1 Article object (primary output, per run)
    topic . layout . title
    abstract (only for scholarly layouts or if explicitly requested;
              otherwise left empty rather than filled with filler)
    answer (first sentence directly answers the question; in newsletter
              mode this is the edition's intro/hook instead)
    takeaways[5-7]  (each synthesizing across 2+ sections; per-item
              quick-hits instead, in newsletter mode)
    sections[] { id, title, markdown body, pull_quote? }
    visuals[]  { section_id, archetype, caption, data drawn only from
              real evidence/attached-file labels — never invented }
    references[]  (deduplicated, numbered, assembled deterministically
              from the [E#] evidence map — never model-written)

4.2 Run-folder outputs (research_runs/<timestamp>_<slug>/)
    topic.txt . options.json . analysis.json . contract.json . plan.json
    evidence/evidence_map.json
    outline/outline.json (+ structural_audit result)
    draft/draft_latest.md . draft/article_latest.json
    audit/verdict_latest.json . audit/gate_latest.json
    visuals/visual_audit.json
    output/article.md  <- the human-readable finished report

4.3 Diagnostics (reported back to the user, not just "done!")
    Final validation status (PASS / PASS WITH WARNINGS / FAIL, honestly —
    a capped repair loop never silently becomes "PASS"), repair-pass
    count, source count, visuals placed, and any warnings (unsupported
    claims, invented entities, structural gaps, visual-audit issues).

4.4 Optional dashboard outputs
    On-screen rendered report (headings/lists/blockquotes/figures) at
    http://127.0.0.1:8787, plus a one-click PDF download. Known
    limitation: dashboard-generated PDFs show figures as bracketed text
    placeholders, not embedded images — output/article.md and the
    on-screen view keep the real figures.

5. FUNCTIONAL REQUIREMENTS (guarantees, all implemented)
--------------------------------------------------------------------------------
FR-1  Outline is a hard contract: outline_contract.py's structural_audit
      checks the proposed outline before writing; enforce fuzzy-matches
      the produced sections back onto it after writing, folding in
      extras and restoring anything missing, deterministically.
FR-2  Human outline checkpoint is a hard stop: research-writer is never
      invoked from an outline that hasn't been explicitly approved,
      edited, or regenerated with feedback. Silence or an unrelated
      follow-up is never treated as approval.
FR-3  Evidence-grounded writing only: every claim traces to a numbered
      [E#] evidence item; evidence-scout is instructed to never invent a
      source, product, statistic, or URL; quality-auditor flags
      unsupported claims and invented entities explicitly.
FR-4  Nine-category structured quality audit (topic alignment, answer-
      contract coverage, evidence support, citation integrity, source
      quality, depth, clarity, coherence, redundancy) judged by
      quality-auditor; quality_gate.py — pure deterministic code, no
      model call — decides accept / targeted rewrite / lighter polish /
      fail. A hard floor on citation-integrity/evidence-support failures
      can never silently become "accept" just because the repair cap
      (default 4 passes) was reached.
FR-5  Visual guardrail: visual-curator never forces a generic figure or
      fetches a stock photo; visual_contract.py deterministically
      requires every placed image to have a caption, point at a real
      outline section id, avoid duplicate archetypes per section, and
      stay under the run's image-count cap. "No visual" is a valid,
      common, correct outcome.
FR-6  Two content types, one pipeline: Article (default, one deep-dive
      report) and Newsletter (--newsletter flag; curated-links edition,
      one intro + one 60-150 word item per evidence source). Only
      outline shape and writing voice change; evidence gathering,
      checkpoint, audit/repair, visual-curator, and publish stay
      identical. outline_contract.py's minimum-depth-indicator check and
      visual-curator's forced-visual behavior are both newsletter-aware.
FR-7  Citation/reference assembly is deterministic: final_publisher.py
      maps [E#] markers to a deduplicated, numbered References list and
      strips any stray marker or model-written reference list — a
      report never shows a literal [E1] to the user.
FR-8  Native multimodal intake: Claude Code reads attached images, PDFs,
      text, and code directly — no separate parsing package to install
      or maintain.
FR-9  Standing knowledge base: research_profile.md, source_rules.md,
      content_rules.md, writing_samples.md, research_memory.md, and
      feedback_log.md are all plain, hand-editable markdown, seeded by
      /setup and refined over time via periodic low-friction feedback
      prompts (cadence set by feedback_every_n).
FR-10 Narrowly-scoped pre-approved permissions: .claude/settings.json
      pre-approves exactly `Bash(python3 *)` / `PowerShell(python3 *)` /
      `Edit(**)` (this project folder only) / `WebFetch` / `WebSearch` —
      nothing broader; an agent attempting any other shell command still
      prompts normally. Effective only after Claude Code's one-time
      folder-trust prompt is accepted in an interactive session.
FR-11 Optional browser dashboard mirrors the CLI pipeline exactly via
      headless mode (`claude -p`) and session-resume (`--resume`) —
      never a parallel or reimplemented pipeline. Never reports a run as
      "done" without finding output/article.md on disk; a missing
      `claude` binary or non-zero exit becomes an explicit error state
      with raw stderr available, never a silent hang.
FR-12 Honest run reporting: every run states its true final validation
      status, repair-pass count, source count, and visuals placed, plus
      any structural/content warnings — never just "done!"

6. NON-FUNCTIONAL REQUIREMENTS
--------------------------------------------------------------------------------
NFR-1 Local-first, zero external service: everything runs inside the
      user's own Claude Code session; the optional dashboard binds to
      127.0.0.1 only; no telemetry, no hosted backend.
NFR-2 Zero-dependency determinism: every scripts/*.py file (and
      ui/server.py) is dependency-free, stdlib-only Python 3.9+ — no pip
      install, no virtualenv, no requirements.txt of the pip-package
      kind. python3 on PATH is the only hard prerequisite.
NFR-3 No separate billing surface: no API key, no .env file, no
      config.py, no provider-routing layer — token spend is whatever the
      host Claude Code session already draws on.
NFR-4 Uniform, user-controllable model tier: all 11 subagents currently
      run model: inherit (whatever model the session is on); any single
      agent's frontmatter `model:` line can be changed to opus / sonnet /
      haiku / inherit independently if a different balance is wanted.
NFR-5 Portability: works on any OS Claude Code + python3 run on; shell
      commands are pre-approved for both the Bash tool and the
      PowerShell tool (native Windows without Git for Windows uses
      PowerShell for shell execution).
NFR-6 Observability: every run's final report is honest about status/
      repair-count/warnings; the dashboard's debug panel exposes the
      exact `claude --resume <session_id>` command so the dashboard is
      never a dead end if it misbehaves.
NFR-7 Encoding correctness: every file read/write across scripts/ and
      the inline one-liners in agent/command markdown explicitly
      specifies UTF-8 — a real, previously-shipped mojibake defect
      (Windows cp1252 misreading UTF-8 em-dashes) that has since been
      found and fixed at all four affected call sites.

7. OUT OF SCOPE (current version)
--------------------------------------------------------------------------------
LinkedIn/social-media posting or scheduling . engagement analytics .
content-pillar planning . multi-user auth/accounts . hosted deployment .
a token-usage ledger (Claude Code doesn't expose per-call token
accounting the way a direct API integration does) . a provider-routing
layer or multiple API keys (one model: the host Claude Code session's
own) . a dedicated Word/PDF export package (the dashboard's bundled PDF
writer covers PDF; Word export is not implemented in this edition) .
non-English UI . automatic scheduled runs . training or fine-tuning of
models.
